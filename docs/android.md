# Android

audiofilus runs on Android phones, tablets, Android handhelds (Retroid, AYN, Anbernic's Android models) and Android TV boxes and TVs as an app built from the same Go code as the iOS one. Work in progress: tested on the emulator (Android 16, x86_64), not yet on a real device, and not published yet.

## How it's built

```sh
mise install                       # zig, the Android SDK (ANDROID_HOME) and JDK 21 (mise.toml)
mise exec -- sdkmanager "ndk;28.2.13676358" "platforms;android-36"   # once, inside the SDK
mise exec -- android/libs.sh       # the C decoders for the APK (android/app/src/main/jniLibs)
mise exec -- android/build.sh      # debug APK; "release" for the release one
```

- `android/build.sh` builds `ebitenmobile` from the same commit of the Ebitengine fork that `go.mod` uses (like the iOS workflow), turns `mobile/` into `android/app/libs/mobile.aar` (`ebitenmobile bind -target android/arm,android/arm64,android/amd64 -javapkg dev.audiofilus`: 32-bit ARM for the TV boxes and Android TVs, almost all 32-bit; 64-bit ARM; x86_64 for the emulator and Chromebooks; one APK with the three, about 60 MB) and runs Gradle. The app version comes from `VERSION` (`0.15.0`), and `versionCode` from it (`1500`).
- **32 bits.** `int` is 32 bits on `armeabi-v7a`: constants and sizes that only fit in 64 bits overflow there (an ID3 frame size past 2 GB made `tagwrite` panic). CI runs the tests with `GOARCH=386` to catch them. Running on 32-bit ARM hasn't been tested on a device: the emulator images here don't translate 32-bit ARM.
- **Android TV.** The activity is also in the `LEANBACK_LAUNCHER` category, the app has a 320×180 `android:banner` (pixel art from `tools/android/icon.sh`: the background, the CD and the name in Jersey 10) and `android.software.leanback` isn't required, so it shows on the TV home screen and still installs on phones.
- `android/libs.sh` compiles **libfdk-aac** (AAC: M4A, M4B, AAC radio) with the NDK and puts it, with the NDK's `libc++_shared.so`, in `jniLibs`. audiofilus loads it with purego by name (`libfdk-aac.so`), which works because the APK extracts its native libraries (`useLegacyPackaging`). fdk-aac's Android build includes the platform's private `log/log.h`, so the script gives it a stub. MP3, FLAC, Ogg Vorbis, WAV, AIFF and ALAC decode in Go; Opus, tracker modules and console music aren't there yet.
- `android/app` is a plain Gradle project in Kotlin, with framework APIs only (no androidx).
- Release signing: `AUDIOFILUS_KEYSTORE`, `AUDIOFILUS_KEYSTORE_PASSWORD`, `AUDIOFILUS_KEY_ALIAS` and `AUDIOFILUS_KEY_PASSWORD` in the environment; without them the release APK is signed with the debug key. The release key (alias `audiofilus`, certificate SHA-256 `16:6B:68:99:…:8B:85`) lives with the author, outside the repo, and in the repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`. Losing it means updates can't be installed over the existing app.
- **Two flavors.** `github` (the release's `audiofilus.apk`) updates itself; `play` (for Google Play, which doesn't allow an app to install packages) doesn't. `android/build.sh [debug|release] [github|play]`; the APKs land in `android/app/build/outputs/apk/<flavor>/<type>/`. What differs lives in `src/github` and `src/play` (`Store.kt`, and the github manifest with `REQUEST_INSTALL_PACKAGES` and `InstallReceiver`).
- **Version and keys.** `android/build.sh` passes `version.Version` (`v` + `VERSION`) and the Last.fm keys (`LASTFM_KEY`, `LASTFM_SECRET`) to Go with `-ldflags`, as `build.sh` does; the iOS workflow too. Without them the app is `dev` and can't update.
- `.github/workflows/android.yml` builds the signed `audiofilus.apk` (by hand from the Actions tab, or from `release.yml` on every release, which attaches it).
- The launcher icon is adaptive pixel art made by `tools/android/icon.sh` (background, foreground and monochrome layers, drawn at 72 px for 108 dp).

## Differences from the handhelds (shared with iOS)

The same as [iOS](ios.md): one process (the audio service in a goroutine, `ui.StartService`), one audio context shared with the interface, the system keyboard, the safe area, and lock screen controls fed by `daemon.NowPlayingHook`. What is Android's own (`android/app/src/main/kotlin/...`):

- **Background music.** `PlaybackService` is a `mediaPlayback` foreground service with the playback notification, started when something plays and taken out of the foreground on pause (the notification stays). Without it Android would kill the process, and the Go service with it, after leaving the app.
- **Media session.** `Media` keeps an `android.media.session.MediaSession`: the notification's controls, the lock screen, headphone and Bluetooth buttons call `Mobile.play`, `pause`, `next`, `previous` and `seekTo`.
- **Where the music is.** Google Play doesn't allow "all files access" for a music player, so the app asks for `READ_MEDIA_AUDIO` (and `READ_MEDIA_IMAGES`, for loose cover images; `READ_EXTERNAL_STORAGE` before Android 13). With it, audio files are readable by their normal paths, which is what the Go code needs. The first time it's granted, the music folder is the phone's `Music`. Settings → Folder opens the system folder picker, and the chosen tree (`primary:Music/Rock`, `1A2B-3C4D:Music`) is turned into its path (`/storage/emulated/0/Music/Rock`, `/storage/1A2B-3C4D/Music`). Files that aren't media (`.lrc`, `.m3u`) are only visible in the app's own folder. Android doesn't let a whole SD card root be picked, only a folder in it. Folders come from the system's storage provider (`primary:…`, `1A2B-3C4D:…`, `home:…` for its Documents root) or as `raw:/storage/…` from some file managers; anything else is reported with a toast. After a folder is picked, a toast says its path and how many items Android lets the app see in it, which tells apart "Android hides the files" from "the scanner misses them". Tested with a Cyrillic folder (`Музыка`) on a virtual SD card. If the audio permission is missing when a folder is picked, the app asks for it again; if the folder still can't be listed by path, it says so (a toast) instead of showing an empty library. `requestLegacyExternalStorage` makes paths work on Android 10, where scoped storage would otherwise block them. The radio lists and MilkDrop presets folders aren't offered on mobile: they live in the app's folder.
- **Android texts** (the notification channel and those toasts) are Android resources, in the same 13 languages as the interface (`res/values-xx`; Indonesian is `values-in`).
- **The app's folder** (`audiofilus.json`, `data/`, the log `data/audiofilus.log`) is `Android/data/io.github.juanvillacortac.audiofilus/files`, reachable from a PC over USB. The socket goes in the cache folder (short path).
- **Self-update** (github flavor). Settings → Update works as on the handhelds: once a day the app checks the latest release; installing downloads `audiofilus.apk` to the cache folder, checks it against `SHA256SUMS` (`update.Fetch`) and hands it to `ui.InstallPackage`, which `Store.kt` implements with the system's `PackageInstaller`: the user confirms, and the first time Android asks to allow audiofilus to install apps (that first attempt is cancelled by the system, so Update has to be tapped again). Android closes the app when it's replaced; it opens again from the launcher. Tested on the emulator from a v0.14.9 build to the published v0.15.0.
- **The app's folder, if unusable.** If `Android/data/...` can't be written, or holds files it can't read (left by an earlier install with another owner), the app uses its internal folder instead (`homeDir`).
- **Back gesture.** Ebitengine only reads Android's Back key as a gamepad's Back button, so the activity catches the system Back (`OnBackInvokedCallback` on Android 13+, which needs `enableOnBackInvokedCallback` in the manifest before Android 16, and `onBackPressed` before 13) and calls `Mobile.back`: it counts as B in the interface (`App.BackGesture`), except in Now Playing with no menu open, where the app goes to the background (`moveTaskToBack`) and the music keeps playing.
- **Gamepads.** With a gamepad connected (at start or plugged in later) the interface is the gamepad one, as on a handheld; touching the screen switches it to the touch one (`Input.padsSeen`, `internal/ui/input.go`). This applies to iOS too.
- **Emulator testing.** `adb shell input tap` presses and releases within one frame, which Ebitengine never sees; use a held tap: `adb shell input swipe X Y X Y 150`.
