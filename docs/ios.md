# iOS

Audiofilus runs on iPhone and iPad as an unsigned app (`audiofilus-ios-unsigned.ipa`), built on GitHub Actions like Trancazo's: install it with [Sideloadly](https://sideloadly.io) or [AltStore](https://altstore.io), which sign it with your own Apple ID.

## How it's built

- `mobile/` is Audiofilus as a Go package for [ebitenmobile](https://ebitengine.org/en/documents/mobile.html): `ebitenmobile bind -target ios` turns it into `ios/Mobile.xcframework`. The ebitenmobile binary is built from the same commit of the Ebitengine fork that `go.mod` uses (its `replace`).
- `ios/project.yml` is the Xcode project for XcodeGen (no `.xcodeproj` in the repo); `ios/Audiofilus/AppDelegate.swift` is the app.
- The app icon is pixel art made by `tools/ios/icon.sh` (the logo's CD over a dithered background with the splash's glows, drawn at 128 px and scaled ×8).
- `.github/workflows/ios.yml` builds it on macOS (by hand from the Actions tab, or from `release.yml` on every release, which attaches the `.ipa`). The repo is public, so macOS minutes are free.

## Differences from the desktop and the handhelds

- **One process.** iOS doesn't let an app start processes: the audio service runs in a goroutine of the app (`ui.StartService`), and the interface talks to it over its socket as usual. The socket path is relative to the app's temporary folder (`AUDIOFILUS_SOCKET`), because Unix sockets can't take paths over 104 bytes and an app's container is close to that.
- **Background music.** `Info.plist` declares the `audio` background mode and the app sets the audio session to playback (`AppDelegate`): the music keeps going with the screen locked, the silent switch on or another app in front. The interface stops drawing while the app is in the background; the service doesn't.
- **Where the music is.** Settings and the library live in the app's Documents folder (`AUDIOFILUS_HOME`), which shows up in the Files app as *On My iPhone → Audiofilus*: anything copied into its `Music` folder plays (it's the default music folder). Settings → Folder opens the system's folder picker (`ui.PickFolder`, `MobileHostProtocol` in Swift) for iCloud Drive, *On My iPhone* or another app's folder; the app keeps a security-scoped bookmark so it can read that folder again on the next launch.
- **One audio context.** oto allows a single audio context per process, and the service and the interface share it here: the interface plays its sounds through the service's output (`ui.SharedAudio`, from `daemon.OnEngine`), and putting it to sleep is the engine's call (`Engine.Idle`: only when no music plays). Before this the interface took the context first and the service couldn't start.
- **When something fails** after start (a panic, an error from Update), the app shows it on screen instead of freezing (Ebitengine stops its loop without closing the app), and everything is logged to `data/audiofilus.log`, visible in Files.
- **The app's folder moves.** Its container (and so the absolute path of Documents) changes with every install: the home Swift passes is used only if it exists (otherwise `$HOME/Documents`), and a saved music folder that no longer exists falls back to the current `Music`. The paths are logged at start.
- **The system keyboard.** When something is typed (the search, a playlist name, a server's address or password), the app opens the iPhone's own keyboard instead of the on-screen pixel one (`ui.ShowKeyboard`, `internal/ui/keyboard.go`): Swift focuses a hidden text field with the current text (a secure one for passwords), every change comes back whole (`MobileKeyboardText`), Return submits (`MobileKeyboardDone`) and lowering the keyboard stops typing (`MobileKeyboardClosed`).
- **Quit** stops the music instead of closing (an iOS app doesn't close itself); "Go to background" isn't needed, leaving the app already does it.
- **Full screen.** The system status bar shows over Audiofilus (light content), and the interface leaves out its own clock and battery on mobile. The safe-area strips above (behind the clock and the island) and below (the home indicator) take the dark of the interface's bars (`DrawInsets`), so the top bar and the button bar seem to reach the edges. The Ebitengine view fills the screen: the animated background reaches the edges and goes under the Dynamic Island, while the interface draws into its own canvas inside the safe area (`MobileSetSafeArea`, sent by Swift on every layout change) placed over it; the interface skips its own background there (`ExternalBackdrop`) so there's no seam, and touches are shifted by the same margin (`SetPointerOffset`). Portrait and landscape both work.
- **Lock screen artwork** comes from the file (embedded, or the folder's image) or, for radios, servers and YouTube Music, from the interface, which sends the cover it has loaded (`ui.NowPlayingArt`).
- **Lock screen and Control Center.** The service calls `daemon.NowPlayingHook` on every song, pause/play and seek change; `mobile` passes title, artist, album, duration, position, state and cover (embedded, or the folder's `cover.jpg`/`folder.jpg`) to Swift (`Host.NowPlaying`), which fills `MPNowPlayingInfoCenter`. `MPRemoteCommandCenter`'s play, pause, toggle, next, previous and position commands (lock screen, Control Center, headphones, CarPlay) call `MobilePlay`, `MobileToggle`... which send the command to the service over its socket.
- <a id="local-network"></a>**Local network.** iOS doesn't let an app send or receive multicast on its own without Apple's `com.apple.developer.networking.multicast` entitlement, so `internal/mdns` hears nothing; only the system's Bonjour is free. Swift implements `mdns.Bonjour` (`Bonjour.swift`, `NetServiceBrowser`/`NetService` on the main run loop, set with `MobileSetBonjour`): `mdns.Browse` asks it for `_googlecast._tcp` and `_mpd._tcp` (instances come back as tab-separated lines with the resolved IPv4, port and TXT) and `mdns.Announce` publishes the MPD server through it. Both service types are listed in `NSBonjourServices`, and the first search asks for the Local Network permission. So on iOS "Send to" finds Chromecasts and MPD servers (other Audiofilus, mpd) and the MPD server works, but DLNA doesn't: SSDP is multicast, so DLNA renderers aren't found and Settings hides the DLNA server and renderer. The services run while the app is in front or playing in the background.
- **Formats.** Those decoded in pure Go (MP3, FLAC, Ogg Vorbis, WAV, AIFF, ALAC) plus **AAC in M4A/MP4** (iTunes purchases) with Apple's decoder: an AudioConverter from AudioToolbox (`internal/decode/aac_ios.go`, cgo, iOS only), fed the track's AudioSpecificConfig wrapped in an ES descriptor as its magic cookie (as FFmpeg does). The AAC source uses an `aacCodec`: libfdk-aac where it exists, the system's otherwise. AAC internet radio (ADTS) works the same way: without libfdk-aac, `adtsStream` splits the stream by its ADTS headers in Go, builds the AudioSpecificConfig from the first header (rebuilding the decoder if it changes) and feeds the raw frames to the system's decoder (`TestADTSStream`). Opus and tracker modules aren't there.
